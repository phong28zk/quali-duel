## Conventions

- **Naming**: kebab-case for all `.ts` / `.tsx`. Long descriptive names beat
  short ones for grep-ability.
- **File size**: target < 200 lines. If a component grows past that, split into
  named sub-components in the same file or a sibling.
- **No barrel-exports for everything**. Contracts have one (`lib/contracts/`).
  OpenF1 internals don't, to keep import paths self-documenting.
- **Pure orchestration, thin wrappers**: every `createServerFn` has a sibling
  `*-impl.ts` that takes the dependency (e.g., `OpenF1Client`) as an
  argument. Tests use the impl directly with a stub.
- **No client-side data fetching**: route loaders are the only way data
  enters the app. Loaders run on the server during SSR and on the client
  during navigation.
- **Schema-validated payloads**: every payload that crosses the
  network boundary (and every payload produced by a builder) round-trips through
  a Zod schema. Bad shapes fail loudly.
- **SVG-first charts**: no chart library. `svg-helpers.ts` is the substrate.
- **Design tokens are the source of truth**: `qualiDuelPalette` for colors,
  CSS custom properties in `tokens.css` for spacing/typography fallback in
  global styles. Components should not hardcode hex.

## Build outputs

- `.output/server/index.mjs` — Cloudflare Worker entry
- `.output/server/wrangler.json` — auto-generated by Nitro
- `.output/public/` — static assets
- `.wrangler/deploy/config.json` — points wrangler at the right config

`pnpm exec wrangler deploy` reads `.wrangler/deploy/config.json` and pushes
the Worker bundle.
